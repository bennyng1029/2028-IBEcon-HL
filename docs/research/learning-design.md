## Learner and learning journey

Audience: an Economics HL beginner who thinks comfortably in science models but writes exams in English. Use precise English exam vocabulary with a plain-English explanation first, followed by optional Japanese, Korean, or Hong Kong Traditional Chinese support. The learner should move from **observe a situation → set assumptions → predict with a model → change one variable → explain the result in English → test when the model fails**. This uses the learner's scientific intuition while making clear that economic models depend on behavioral and institutional assumptions.

Recommend a guided, model-led lesson path as the primary experience. A lesson should have: (1) a familiar choice or policy question; (2) an explanation of the relevant English term in one short sentence; (3) an interactive diagram or small data table with named assumptions; (4) a prediction prompt before the control moves; (5) a concise explanation of the causal chain; (6) one counterexample or limitation; (7) a short exam-style response with feedback criteria. This full sequence is a recommendation; several individual elements also appear in the chemistry reference, as documented above.

Keep a syllabus map and searchable glossary as secondary entry points so a student can jump to a topic during revision. Another viable direction is an encyclopedic topic reference first: faster to populate and good for lookup, but less effective for a novice learning causal reasoning. A third is an exam-practice first site: useful close to assessment, but students may imitate diagrams without understanding assumptions. The guided path can still link to compact reference and exam practice.

Align the map with the four IB units, while explicitly marking first-release coverage as a product decision. If the first release covers Units 1–2, show Units 3–4 as forthcoming rather than implying full HL coverage. The curriculum has introductory opportunity cost and production possibilities before microeconomic demand and supply; later units extend the same model reading habits to aggregates, exchange rates, development, and policy. Tag each lesson with its unit, English terms, diagram skill, quantitative skill if relevant, and a key concept. Use the IB's nine key concepts as recurring lenses rather than a disconnected vocabulary list.

## Candidate interactive models

Each interaction should be deterministic, local to the browser, and accompanied by a text/table representation. Quantities below are **teaching examples**, not measured real-world relationships.

| Model | Learner action and expected insight | Explicit assumptions and boundary |
| --- | --- | --- |
| Scarcity and opportunity cost / production possibilities curve | Allocate a fixed resource between two goods; see feasible points, an unattainable point, and the next-best alternative forgone. Ask why a point inside the curve is possible. | Fixed resources and technology; two goods; curve shape is illustrative. Inefficiency is one possible reason for an interior point, not proof of its cause. |
| Competitive market demand and supply | Move a demand or supply shifter after predicting price and quantity; distinguish a shift from movement along a curve and narrate the new equilibrium. | Stylized competitive market, other determinants held constant, stable curves, and a clear time horizon. Never label a price change alone a curve shift. |
| Price ceiling and indirect tax | Set a ceiling below equilibrium or add a per-unit tax; compare quantity traded, shortage/surplus where applicable, consumer/producer prices, tax revenue, and a simple welfare area. | Enforcement/compliance, linear curves and static partial equilibrium; welfare areas require stated willingness-to-pay and cost interpretations. Avoid presenting incidence as always falling on a fixed side. |
| Price elasticity of demand | Adjust demand slope or compare two point changes; calculate percentage changes and explain the difference between elastic and inelastic responses. | State the elasticity method and range. Slope is not elasticity; responsiveness can vary along a linear curve. |
| Externality | Introduce marginal external cost or benefit and compare private and social outcomes, then vary a policy instrument. | Marginal curves are simplified and knowledge of external cost/benefit is assumed. Label any welfare loss as model-dependent, not a measured number. |
| AD–AS or exchange-rate extension | For later units, change one named determinant and predict output/price level or currency value, then test a limitation. | Make model version, exchange-rate regime, short-run horizon, and ceteris paribus conditions visible. Avoid mixing long-run and short-run claims. |

For every model, show a visible initial state, a reset action, numeric values with units, axes and curve labels, a short textual state summary, and a worked calculation where arithmetic is assessed. Permit keyboard entry of control values so dragging is optional. When a result depends on parameter choices, display those choices beside the claim.

## English exams and multilingual support

Use one canonical English concept ID per term (for example `opportunity_cost`, `equilibrium`, `price_elasticity_of_demand`) and maintain hand-reviewed strings for `en`, `ja`, `ko`, and `zh-Hant-HK`. A manual language switch should be visible on every page, preserve the current topic, and store the preference locally if the student allows ordinary browser storage. English is the fallback for missing translations, with the untranslated section visibly labeled. Never silently mix a stale translation into an updated explanation.

Keep English exam terms visible even when explanatory prose changes language: e.g. **opportunity cost** followed by the selected-language explanation. Preserve English command terms such as *explain*, *analyse*, and *evaluate* in prompts, with a translated gloss and an example of what the command asks the student to do. Diagram axis labels, formula names, and response templates should remain available in English. A language toggle should change instructional prose and interface labels, not alter the mathematical model or accepted answer.

Quality workflow: write the plain-English source first; have a subject-aware human translate or review each locale; check term consistency against the bilingual glossary; perform a second review for economics meaning, register, and Hong Kong Traditional Chinese usage; test long strings and punctuation in the actual layout. Track source revision and locale review status per lesson. Avoid machine translation at runtime and avoid language claims beyond the reviewed content. For exam practice, make the expected final answer English even when hints are translated.

## Access and mobile constraints

Use semantic headings, labels, buttons, and visible focus; all interactive outcomes must be reachable by keyboard. Provide a table and short narrative equivalent for every graph so a learner can inspect values without seeing color or a plotted line. Distinguish curves through labels/patterns as well as color, announce changed results to assistive technology without flooding it, and respect reduced-motion settings. Controls should work on narrow screens without horizontal page scrolling; place controls before or beside a responsive graph, with axis labels still readable. Use generous touch targets and avoid hover-only explanations. The [W3C WCAG 2.2 recommendation](https://www.w3.org/TR/WCAG22/) is the source for keyboard operation, reflow, language identification, and target-size criteria; validate the built pages against those criteria rather than assuming a chart library makes them accessible.

For a static deployment, keep lessons, diagrams, translation strings, and answer feedback in first-party files. Use no runtime AI, backend, account, or new dependency. Store optional progress only in the current browser, make it exportable or resettable if progress is offered, and avoid implying cross-device sync. Give explanations for model outputs rather than a bare correct/incorrect signal.

## Checkable design outcomes for a later implementation plan

- A new student can open a Unit 1 lesson, state its assumptions, predict a diagram change, and write a short English causal explanation using the named exam terms.
- Each interactive model has a keyboard-accessible path and a text/table equivalent yielding the same result as the graph.
- A manual locale switch preserves topic and displays reviewed `ja`, `ko`, or `zh-Hant-HK` explanations while English exam terms remain visible.
- Syllabus navigation distinguishes released from unreleased content and maps every released lesson to an IB unit.
- The published site runs as static files with no network request needed for model calculations, translation, or answer feedback.
